# Security

Do not paste credentials, authentication files, real meeting materials, full generation context, or unredacted logs into public issues or pull requests.

Use GitHub private vulnerability reporting when enabled. Otherwise, open an issue without sensitive details and ask the maintainer for a private reporting channel. Do not publish exploitable confidential information while establishing contact.

If a credential was committed or exposed, revoke or rotate it with its issuer first. Deleting a current file or adding an ignore rule does not erase earlier commits, branches, tags, forks, or downloaded copies. History rewriting requires coordination and is not performed by the publication checker.

For ordinary bug reports, include software versions, anonymous reproduction steps, the error category, and fictional sample data. Microphone capture and real model access must be explicitly initiated by the person testing.

Sidecue is a development preview. There is no independently signed or notarized distribution, and no formal security audit has been completed.
